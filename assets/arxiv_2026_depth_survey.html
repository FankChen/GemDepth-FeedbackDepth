0. 一句话结论

这批新工作里，真正对我们有杠杆的只有四条，其余是背景。 ① CVPR'26 的 CARVE 用系统消融给出「梯度匹配 loss 可能是负收益」「per-sequence + per-frame 双对齐才对」—— 我们的 VideoDepthLoss 两条都踩了，而且是一行改动就能验的； ② ICLR'26 的 PAGE-4D 指出位姿头与几何头在动态区域天然冲突，这给了 Sintel 长尾崩溃一个可证伪的机理假设； ③ SelfEvo 用无标注真实视频自蒸馏拿到 video depth +36.5%，正好绕开我们「Stage-2 拿不到 IRS / 野外立体视频」的死结； ④ PXDepth 把多尺度解码头的天花板归到 tokenization 粒度 而非尺度数量—— 这提示应检查真正的高分辨率图像特征流；我们现有 full-res arm 只插值已有特征， 不能据此验证或否定 PXDepth 的机制。
对多尺度解码头这条线，外部证据和我们自己的证据现在指向同一个方向：收线。 见 VKITTI 八 arm 看板——八个 arm 无一赢过 temporal，差距是种子噪声带的 10–18 倍。 新论文里 DPNeXt（减参 78.6% 反而更好）、VDPP（精修该在低分辨率做）、PXDepth（插值补不回 tokenization 损失） 都是同方向的旁证。继续在现有头上加模块，先验概率很低。

2. loss 设计 —— 最高价值，而且是一行改动

CARVE：Unlocking the Power of Critical Factors for 3D Visual Geometry Estimation

arXiv:2604.21713 · CVPR 2026 · Guangkai Xu, Hua Geng, …, Hao Chen, Chunhua Shen（浙大 AIM 组）· github.com/aim-uofa/CARVE
它的出发点和我们的困境几乎一模一样 “multi-frame models usually produce better cross-frame consistency, yet they often underperform strong per-frame methods on single-frame accuracy.” ——这正是我们「多尺度 / GEM 一路加时序与几何模块，却始终追不上朴素 temporal」的处境。 它没有提新架构就发了 CVPR，靠的是把消融做干净。
CARVE 的消融结论 我们代码里的现状 动作
① gradient-based loss 可能反而有害 loss/videoloss.py 的 TrimmedProcrustesLoss.__alpha = 0.5， 即 total = ssi + 0.5·gm，正是论文的 L_ssi + 0.5·L_gm。 这个 0.5 从头到尾没动过、也没验过。 alpha=0 的单变量消融。 GemDepth 论文本身也没做这个 ablation， 拿到任一方向都是新信息。
② per-sequence + per-frame 联合对齐更好； local region 对齐反而更差 compute_scale_and_shift 在 flatten(1,2) 之后对 dim(1,2) 求和 → 整段 clip 只有一组 (scale, shift)，纯 per-sequence。 加一路 per-frame 仿射对齐项。 注意 CARVE 说 local region 更差， 不要顺手做成分块对齐。
③ 数据多样性 / 质量 scaling 即使在 SOTA 上仍有收益 我们的配比偏差已量化：PointOdyssey 36.2% / TartanAir 35.4% / MVS-Synth 25.8% / VKITTI2 1.4% / DynamicReplica 1.3%。 mix_policies.uniform 已实现，待起 arm（§4）。
④ 新增 consistency loss： 强制 depth / camera / pointmap 三者对齐 CameraLoss 只把 pose_enc_list 与 GT pose 比 L1， 位姿与深度之间没有任何一致性约束。 用 GEM 自估位姿把 t 帧深度 warp 到 t+1 帧比对。 这条最像能写进论文的方法贡献， 且复用已有的 camera_head，不加新模块。
⚠ 落地时的代码组织约束 train.py:457 是 VideoDepthLoss(pose_flag=pose_flag)， alpha 一路硬编码到 TrimmedProcrustesLoss 默认值。 按仓库硬规则（核心代码不堆 if/else，走注册表）， 正确做法是照 mix_registry / freeze_registry 的样子加一个 loss policy 注册表， 新 loss = 新模块 + @register，差异走 config，而不是给 train.py 再加分支。

3. Sintel 长尾崩溃 —— 一个可证伪的机理假设

已知事实 Sintel 23 条序列 AbsRel 从 0.054 到 1.53，均值 0.3195 但中位数只有 0.2163， 被最差 2–3 条（RMSE 19.1 / 25.5）拉高。 这是长尾问题，不是普遍差——改进应该针对那几条崩溃序列。

PAGE-4D：Disentangled pose and geometry estimation

arXiv:2510.17568 · ICLR 2026 · page4d.github.io

核心张力，原文：

accurate camera pose estimation requires SUPPRESSING dynamic regions,
while geometry reconstruction requires MODELING them

它的解法是 dynamics-aware aggregator 预测一张 dynamics mask：对 pose 分支抑制运动线索、对 geometry 分支放大。

为什么这可能就是我们 Sintel 崩溃的机理 GemDepth 的 L_cam 梯度路径是 camera_head → global/frame_blocks → camera_token/register_token → feats[3]， 与 depth head 共享同一个 backbone。 而 Sintel 恰好是合成非刚体 + 大幅镜头运动——正是这个张力最尖锐的场景。 KITTI（刚体为主）只有 1 条 0.1733 的轻微离群，也与该假设一致。
✅ 建议先做这个：零训练、~1 小时、二值结论 对那 2–3 条崩溃序列，推理时把 pose_enc_list dump 出来， 看 GEM 自估位姿的误差是否在同样的序列上同步爆炸。
  • 位姿也爆 → 坐实 pose / geometry 打架，PAGE-4D / TrajVG 路线有据可依，可以立项
  • 位姿正常 → 干净排除该假设，省掉一整条错误方向
不用训练、不用重跑评测，只要改推理脚本 dump 一个张量。

4. Stage-2 数据缺口 —— 有替代路线了

已验证的前提 Stage-2-lite 是干净的 null result（kitti +0.9% / sintel +0.9% / bonn −0.4%，全在 ±1% 内）。 → 机制 B（消除移动靶）与 C（释放容量）均不成立， 论文 Stage-2 的收益几乎全部来自「引入真实数据」，而非「冻结 GEM」这个训练技巧。 而真实数据我们拿不到：IRS 唯一入口是 OneDrive（Bosch / 阿里云代理都挡，HF 无镜像）， 野外立体视频是作者自采。

SelfEvo：Self-Improving 4D Perception via Self-Distillation

arXiv:2604.08532 · Nan Huang, …, James M. Rehg, Angjoo Kanazawa, Haiwen Feng, Qianqian Wang · self-evo.github.io

用无标注视频做自蒸馏，机制是 spatiotemporal context asymmetry： teacher 拿到更长 / 更全的时空上下文，student 只看受限上下文，两者的差就是监督信号。 八个 benchmark 一致提升，跨 base model 通用（VGGT 与 π³ 都涨）， video depth 最高 +36.5%、camera +20.1%，零标注。

为什么这条对我们特别合适
  • 无标注真实视频不受任何代理墙限制——本地已有的 KITTI raw、任意公开视频都行， 绕开了 IRS / 野外立体视频这个死结
  • 我们已有训练充分的 Stage-1 ckpt 可以直接当 teacher，起点比论文强
  • 直接对准我们自己已验证的诊断（差距大头是真实数据蒸馏，不是头的结构）
  • asymmetry 的实现方式与 GemDepth 结构天然契合： teacher 吃 seq_len=32 全序列，student 吃短窗口 / 丢帧—— 而丢帧机制我们代码里已经有了（_pose_input_mask 那套的训练分支）

5. 多尺度 / 解码头 —— 外部证据继续负面

先摆我们自己的账（八 arm 看板） KITTI zero-shot：temporal 0.0981 → nofp32 0.0991 → depth_concat 0.1004 → finealone 0.1016 → grad 0.1066 → errmap 0.1076 → gem 0.1082 → norm 0.1094。 八个 arm 无一赢过朴素 temporal，差距 0.006–0.011 = 种子噪声带（0.0006）的 10–18 倍。 唯一较纯的 ms vs finealone 是 0.1004 vs 0.1016， 粗尺度辅助监督可能微正，但差值小且只有单 seed；norm 对比还混入了最细尺度权重变化。 更早的 mixdata 同配方对照里，多尺度头四集也输 temporal 三集。
PXDepth 给了这个现象一个解释 arXiv:2608.16984（2026-08-17，Zhiyuan Yuan, Guanying Chen 等）原文诊断： “large-patch ViT encoders + convolutional decoders … coarse tokenization can weaken pixel-level cues that upsampling cannot fully recover.” 它的解法是 Context-Modulated Pixel Transformer —— 大 patch ViT 只负责全局上下文， 像素级预测器全程保持高分辨率，而不是先在低分辨率卷完再插值。

这提出了一个与我们旧 arm 不同的机制：瓶颈可能在高分辨率图像线索，而非尺度数量。 我们的 fullres_mode 系列（E1/E2b 在 448² 上四层全卷，5–7.4 s/it） 试的正是「插值到 full res 再卷」——按 PXDepth 的说法，这条路先天补不回来， 这也解释了为什么 E1/E2a/E3/E4 四者互相在噪声带内不可分。
论文说了什么对我们的含义
DPNeXt
2607.16012 · IROS'26		 DPT decoder 就是瓶颈；换成 dual depthwise separable inverted bottleneck， 可训练参数 −78.6% 反而更好 它支持“效率也值得优化”，但不能佐证旧的 4× 容量归因： 我们实测 head 仅从 71.8M 增到 73.2M（约 2%）
VDPP
2604.06665 · CVPR'26 W		 把精修从「昂贵的场景重建」改成「纯低分辨率几何精修」， RGB-free，Jetson Orin Nano 上 43.5 FPS 我们在 full-res 上卷了 E1/E2b 半天没收益，正好反向印证
PixelUp
2608.02792		 zero-shot、VFM-agnostic 上采样器， coarse-to-fine windowed cross-attention + 多尺度语义引导，NYUv2 δ1 +0.25 最便宜的可试项：即插即用替换 DPT refinenet 的上采样， 不改训练配方、不改 loss
Pixel-Perfect Depth
2601.05246		 pixel-space DiT + Semantics-Prompted DiT + Cascade DiT（逐级增加 token 数）；视频版 PPVD 用 reference-guided token propagation 保时序 它的 coarse-to-fine 是在 token 数 上做， 不是在空间分辨率上做——与我们 28/56/112/224 的做法是不同的轴
DegBins
2605.09628		 多阶段 c2f，但把残差建模成 classification-regression 混合 （深度 bins 的概率加权），每阶段更细的 bin 划分 ⚠ 注意它是 depth super-resolution 不是 MDE，不可直接照搬。 但「换建模方式而非加层数」这个思路对我们的纯残差回归 delta_i 有参考价值
建议（诚实版） 两条路选一：
  • ①收线：把它写成一个干净的负结果—— 「在 DINOv3-ConvNeXt / DINOv2-ViT + DPT 范式、匹配配方下， coarse-to-fine 残差精修头不优于单尺度 temporal 头； 现有单 seed 结果不足以把差异归因到粗尺度深监督、容量或 loss 标度」。 这是当前证据能支持的边界，后续结论需匹配 objective 与多 seed。
  • ②换范式：PixelUp 当上采样器（最便宜，不动训练） 或 PXDepth 式 context-modulated pixel-space 预测器（要改结构）。 不要再在现有头上 +层 +参数。

6. 两个便宜且我们没试过的正杠杆

a) 时间轴深度反馈

VeloDepth / Video Depth Propagation · arXiv:2512.10725 · Luigi Piccinelli, …, Luc Van Gool（ETH）· github

Propagation Module = 光流 warping + learned residual corrections， 把上一帧的 depth feature 与 prediction 一起传播过来，结构性地强制时序一致。

为什么值得试 我们的 depth_feedback 是把上一尺度的深度喂回去（空间轴）， 实测是 E2a 那次的正杠杆、而且是最便宜的一个（~5.5h）。 同一个 idea 换到时间轴我们从没试过， 有自己的正结果背书，成本一次 20k 步。

b) 显式点对应，替代隐式时序注意力

Tracktention · arXiv:2503.19904 · CVPR 2025 · Zihang Lai, Andrea Vedaldi（VGG）

用 point tracks 显式做时序对齐，作为一个 layer 插进 ViT， 能把 image-only 模型升级成 video 模型，有时反超原生视频模型。

与 ASTT 的关系 GemDepth 论文对 ASTT 的原话是 “captures latent point-level correspondences”。 Tracktention 就是把这个 latent 的东西显式化—— 这是一个结构清晰、好写、且直接站在原论文自己叙述上的 “GemDepth++” 假设。
⚠ 一条我先前提过、现在要打折的 Rethinking the State Update Gate(2605.16981) 的帧级标量门是闭式解、零参数零训练，Bonn video depth AbsRel −12.8%，很诱人。 但它针对的是 recurrent / 常数显存的流式模型（TTT3R / CUT3R 那一族的 state token）。 GemDepth 不是 recurrent、也没有压缩状态，不能直接套。 只有「按帧间特征变化调制该帧对时序聚合的贡献」这个抽象思想可借。

8. 建议的执行顺序

#动作 成本拿到什么
1 Sintel 崩溃序列 dump pose_enc_list， 看位姿误差是否与深度误差同步爆 零训练 ~1h 证实 / 证伪 pose-geometry 打架假设， 决定要不要走 PAGE-4D 路线。二值结论，没有中间态
2 alpha=0（去掉 L_gm）单变量消融 1×20k 步 直接检验 CARVE 结论①。 GemDepth 论文没做过这个 ablation，任一方向都是新信息
3 per-frame + per-sequence 双对齐 SSI 1×20k 步 CARVE 结论②；顺带可能解释 500 帧协议的系统性劣化
4 「mix=uniform + 6 分辨率训练」合成一个 arm 1×20k 步 补齐两处已知复现偏差，得到可辩护的新 Stage-1 baseline。 uniform 已实现，只差多分辨率
5 depth↔pose 一致性 loss（GEM 位姿 warp 深度） 1×20k 步 最像方法贡献的一条，复用已有 camera_head，不加新模块
6 SelfEvo 式自蒸馏（无标注真实视频） 需写 pipeline 补 Stage-2 数据缺口，是我们已验证诊断的直接后继动作
⚠ 三条前置条件（按仓库自己的实验对照硬规则）
  • GEM 模型至今没有实测的种子噪声带。 现有的 ±0.0006 那条量自 E2a_feedback（use_gem=false）。 上面 2–5 号的预期增益量级可能就在 1–3%， 不先测出 GEM 系的噪声带，结果读不了。 建议在起 method arm 之前，先跑 2–3 个种子的 stage1_repro。
  • 评测协议锁死 500 帧。 已证实短协议系统性偏乐观（kitti +10.8% / bonn +35.5% / scannet +13.8%）， 且 sintel 未切 500 的那次只差 +0.2%，反证流程本身无偏差。
  • 新增 loss 走注册表，不给 train.py 加分支。 照 dataset/mix_registry.py 与 model/freeze_registry.py 的样子来。
已经不需要做的（相对两天前的判断）
  • 位姿 dropout P0 不再是拦路虎。 实测 stage1_repro KITTI 500 帧 0.086233 → 0.086110， 逐序列最大差 0.00054。当初「会淹没 1–3% 方法增益」的判断说大了两个数量级。
  • 数据配比修正已落地一半：mix_policies.uniform 已实现并有单测， 五个源都落在 19.6%–20.4%。

VKITTI 多尺度头 vs Temporal 基线 —— 对照实验看板

PP-DPT · 分支 feat/registry-mixdata (PR#8 注册表重构后) · 训练 2026-08-21 → 08-24 · 阿里云 DSW 8×H20 · 评测日期 2026-08-24

0. 一句话结论

八个 arm，没有一个赢过朴素的 temporal 基线。 KITTI zero-shot 上的排序几乎就是“越简单越好”： temporal 0.0981 → nofp32 0.0991 → depth_concat 0.1004 → finealone 0.1016 → grad 0.1066 → errmap 0.1076 → gem 0.1082 → norm 0.1094。 差距 0.006–0.011，是种子噪声带（0.0006）的 10–18 倍，不是噪声。 拆开看：粗尺度深监督几乎不贡献（−1.2%），真正起作用的是最细层的监督强度（+7.7%）； GEM 在这个规模上是负收益（+7.8%）；errmap 相对 GEM 是 null（−0.6%）。 目前没有任何证据支持多尺度头、GEM 或 errmap 在此配方下优于 temporal。
但“域内赢 / 泛化输”这个叙事目前只剩一半证据。 域内 dense 只测了最早的三个 arm（§2.1），新增的五个还没跑。 在补齐之前，“翻转是过拟合”只是假设，不是结论。
✅ 位姿 dropout P0：对本页结论无影响，且实测量级远小于当初估计。 model/gemdepth.py 的位姿 dropout 曾缺 self.training 守卫，08-24 已修。
  • 六个无 GEM 的 arm 完全不受影响 —— 那段代码在 if self.use_gem: 里，根本不执行。
  • ms_gem / ms_errmap 确实开了 GEM，但它们训练与评测都在修复之后，拿到的是确定性结果。 （注：93fae0c 之后 ConvNeXt 已可开 GEM，早先“ConvNeXt 结构性免疫”的说法已失效。）
  • 实测量级：stage1_repro 在 KITTI 500 帧上重测，0.086233 → 0.086110， 逐序列最大差 0.00054、均值差 0.00012。当初“会淹没 1–3% 方法增益”的判断说大了两个数量级。

2.2b 这八个 arm 到底差在哪（白话版）

先说共同点。八个 arm 用同一个骨干（DINOv3 ConvNeXt-S + LoRA）、同一份数据（VKITTI2，1010 clips， 按场景留出测试集）、同样 10000 步、同样有效 batch 32、同一个 seed、同样的评测口径。 所以任意两个之间的差别，只来自下表「改了什么」那一栏。
arm白话：它到底做了什么 改自单一变量KITTI
temporal 基线 最朴素那版。只在最终分辨率出一张深度图，中间不分档，没有任何附加模块。 ——0.0981
ms_depth_concat 改成由粗到细分四档：先出一张很模糊的深度图，再把它当参考画清楚一点，重复四次。 四档都打分，分数相加。 基线换成多尺度头0.1004
ms_nofp32 跟上面完全一样，只是最后一层卷积用低精度（bf16）算，而不是高精度（fp32）。 纯数值精度开关，不改结构。 depth_concat最后一层的数值精度0.0991
ms_norm 四档的分数从相加改成取平均。 副作用：最终那档的打分权重从 1.0 掉到 0.25 —— 见 §2.3。 depth_concat四档分数求和 → 取平均0.1094
ms_finealone 同一个四档结构，但只给最后那档打分，前三档草稿不打分。 depth_concat粗档监督：开 → 关0.1016
ms_grad 基础版里，每档参考上一档时会切断反馈（depth_prev.detach()）， 等于四个档各学各的、只是多看一张参考图。这版去掉切断，让四档串成一条真正端到端的链。 depth_concat跨档梯度：断 → 通0.1066
ms_gem GEM 打开 GEM：多一个模块去估计相机在帧之间怎么移动， 把这个几何信息喂给深度网络。想法是"知道相机怎么动，就能靠三角测量算距离"。 depth_concatGEM：关 → 开0.1082
ms_errmap GEM 在 ms_gem 之上再加自检：用当前深度 + GEM 给的相机运动，把前后帧「扭」到当前视角比一比， 哪里对不上就说明哪里可能猜错了，把这张「疑似出错图」喂回去让它自己修。 ms_gem光度自检：无 → 有0.1076

继承关系：谁该跟谁比

temporal 基线（什么都不加）  0.0981
      │
      └─ ms_depth_concat  0.1004  ─┬─ ms_nofp32     0.0991   只换数值精度
                                   ├─ ms_norm       0.1094   四档打分改取平均
                                   ├─ ms_finealone  0.1016   只给最后一档打分
                                   ├─ ms_grad       0.1066   四档之间不再切断反馈

⚠ 只能沿着这棵树的边比，不能跨枝比。 例如 ms_errmap 的对照是 ms_gem（两者都开 GEM）， 不是 ms_depth_concat —— 后者关着 GEM，跨过去比会把「加 GEM」和「加自检」两件事混在一起。
一个容易被忽略的结果：ms_grad 说明「切断反馈」原本是在帮忙。 基础版四档之间是 detach 断开的，看板 §3 曾把这点当作缺陷记下来（"实质是 4 个独立头共享骨干， 不是真正的端到端 coarse-to-fine"）。ms_grad 把它接通之后 0.1004 → 0.1066，+6.2% —— 接通反而更差。 在这个数据量下，让四档互相牵扯只会把误差沿着链条放大，各学各的更稳。

2.3 干净的两两分解（本轮核心结果）

✖ 先订正一条：ms_norm 是个设计坏了的消融。 它并不“只去掉四尺度求和带来的梯度放大”。看 loss/multiscale_videoloss.py： normalize_scale_weights 就是 weights = [w / weight_sum ...]。 于是它把最细层的监督也一并砸到了 1/4 —— 而最细层正是唯一被拿去评测的那一层 （eval 取 scale_depths[-1]）。所以 0.1094 这个全场最差反映的是“最细层欠训”， 不是“去掉混淆后的真实水平”。看板早先把它写成“消掉 B”，那个说法作废。
arm最细层权重各粗层权重总量KITTI AbsRel
ms_depth_concat1.01.04.00.1004
ms_finealone1.001.00.1016
ms_norm0.250.251.00.1094
① 粗尺度深监督值多少？几乎为零。 depth_concat vs finealone —— 最细层权重都是 1.0，唯一差别是粗层监督开/关： 0.1004 vs 0.1016 → 加上粗层监督 −1.2%。 这是对“多尺度深监督（假设 A）”的直接否定，与 7 月 E 系列消融（四变体统计不可分）方向一致。
② 最细层监督强度值多少？很多。 ms_norm vs finealone —— 总量都是 1.0，只差最细层是 0.25 还是 1.0： 0.1094 vs 0.1016 → −7.7%。 真正起作用的是最细层的监督强度，粗层几乎不贡献。
③ GEM 在这个规模上是负收益。 depth_concat 0.1004 → ms_gem 0.1082，+7.8%。 同一个头、同一份数据、同样 10k 步，只加 GEM，KITTI zero-shot 就差 7.8%。
④ errmap 是 null。 ms_gem 0.1082 → ms_errmap 0.1076，−0.6%。 在 GEM 之上加 errmap，基本没有变化。这是 P1 核心工作线的第一个对照数据。 Caveat 仅 VKITTI 单数据集 / 1010 clips / 10k 步 / 单 seed，不能直接外推到 stage1 那种 690k 数据的配方。 但在本规模验证里，errmap 没显出效果。

3. 代码层面：ms 相对基线多了什么

基线出深度（model/dpt_convnext.py）

path_1 = refinenet1(...)                 # 224²
out = scratch.output_conv1(path_1)       # 256 → 128
out = interpolate(out, 448²)             # 特征先上采样
with autocast(enabled=False):            # ← 无条件 FP32
    out = scratch.output_conv2(out.float())   # 128 → 32 → 1

多尺度头（model/dpt_multiscale_convnext.py）

for i, feat in enumerate([path_4(28²), path_3(56²), path_2(112²), path_1(224²)]):
    out_size = min(feat*2, 448)                        # 56 / 112 / 224 / 448
    f = output_conv1_heads[i](feat)                    # 256 → 128
    f = interpolate(f, out_size)
    e = depth_encoder(resize(depth_prev.detach()))     # 1 → 32   深度反馈
    delta = delta_heads[i](cat[f, e])                  # 160 → 32 → 1
    depth_i = resize(depth_prev).detach() + delta      # 残差累积
训练返回 4 个尺度；eval 返回 scale_depths[-1]（448²，与基线同分辨率）
结构上，ms ≈ 把基线的 output_conv1/output_conv2 在四个尺度各复制一份，再给每份额外喂一张上级深度图。

4. 关于 multiscale_fp32_head（一条订正）

订正：在本次对照里 fp32_head: true 才是同口径的那个 arm。 基线的 scratch.output_conv2 在代码里是 无条件 FP32（with autocast(enabled=False) 写死）。 师兄 config 开 true 是刻意与基线对齐，不是随手打开的。 我们额外加的 nofp32 arm 反而多引入了一个变量。
历史上"fp32_head 是负结果"的结论不适用于此处。 那来自 mixdata 配方下 E2a/E4 两组消融（各退化约 0.003 ≈ 种子噪声 5 倍），是另一套代码与数据配比。 本次两个协议还打架：VKITTI 域内 fp32 更好（0.1123 vs 0.1155），KITTI 上 nofp32 更好（0.0991 vs 0.1004）， 差距 0.0013–0.0032，在本次样本量下判不出优劣。

5. 必须标注的局限（诚实清单）

  • VKITTI 域内样本量极小：1 条 held-out 序列 / 268 帧。历史实测的种子噪声带是 AbsRel ±0.0006（在四集 benchmark 上），单序列方差只会更大。
  • VKITTI val 帧训练时见过：train split 的 end_idx = round(seq_num) = 0–100%，val 取后 10% 落在训练集内。域内数字系统性偏乐观，只能当 sanity / 对照，绝对值不可对外引用。
  • 单 seed：三个 arm 都只有 seed 0。KITTI 上 2.3% / 1.0% 的差距未经多种子确认。
  • loss 尺度不匹配：见 §1 的对照缺陷，尚未消除。
  • 头结构已与历史 E 系列不同：PR#8 之后是"特征先上采样再出残差 + depth_feedback 恒开"，fullres_mode 退化成死开关。 不能把本次数字与历史 C / E1 / E2a / E3 / E4（0.0915–0.0946 那批）横向比较。
  • KITTI 用 110 帧短协议（kitti_video.json），不是论文的 500 帧协议。短协议对视频方法系统性偏乐观（实测 kitti 短→500 会劣化约 10.8%）。

8. 本轮踩坑记录

  • 首轮两个 ms arm 全部 Exit 1：TypeError: MultiScaleVideoDepthLoss.__init__() got an unexpected keyword argument 'normalize_scale_weights'。 根因是阿里云工作树版本错配——train.py 是新版会传该参数，loss/multiscale_videoloss.py 还是旧版。 起因是之前用 git checkout FETCH_HEAD -- <部分文件> 挑文件时漏了 loss/。 修法：git checkout FETCH_HEAD -- loss/multiscale_videoloss.py。
  • torchrun 只在末尾留 <NO_OTHER_FAILURES> 尾巴，真因在其上方的 Root Cause 段 —— tail -2 看不到，要 tail -60。
  • 日志里 tqdm 的 \r 会把后续 print 挂在同一"行"上，grep "^\[loss\]" 只匹配到第一条； 要先 tr '\r' '\n'。含控制字符的日志还需 grep -a，否则报 "binary file matches"。
  • 多尺度未退化：step 0 四尺度 total_loss = 3.3313 / 3.2473 / 2.8966 / 3.3724（不全等）， 历史上"多尺度塌缩成单尺度"的老毛病没有复发。

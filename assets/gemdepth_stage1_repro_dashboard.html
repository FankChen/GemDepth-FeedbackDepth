四、与论文 Table 1 的粗定位 口径不同，不可直接比

Table 1 是完整两阶段训练的最终模型。列序与论文一致：Sintel / KITTI / Bonn / ScanNet（AbsRel ↓）。

方法SintelKITTIBonnScanNet延迟

⚠ 绝不能声称"超过论文 SOTA"，尽管 Bonn（0.0513 vs 0.066）与 ScanNet（0.0676 vs 0.071）数字上更好：
  • 评测帧数不同：我们的 four-bench 是 KITTI 110 / Sintel 100 / Bonn 110 / ScanNet 90 帧；论文是 Bonn·ScanNet·KITTI 各 500 帧、Sintel 50 帧。 帧数少对视频方法系统性偏乐观——漂移积累更少，且仿射对齐在更短序列上拟合得更好。
  • 训练阶段不同：Table 1 是完整两阶段（940K 帧），我们只有 Stage-1。
跨 Table 1 的比较只能作粗定位，第三节的 Table 4 才是我们真正对上的基准。

八、复现过程中修掉的坑

#问题根因修法
1CLI override 报 Key 'total_step' is not in structconfig 移入子目录后缺 # @package _global_，Hydra 把整份配置嵌套进目录包补上该行（师兄的 44 个 config 都有）
2GEM 训不动参数分组里只有 ASTT 走 dec_lr，GEM 和预训练 head 一起落在 other_lr=1e-6抽出 NEW_MODULE_PREFIXES，GEM+ASTT 同归 1e-4
3加载 VDA 触发"必须零 missing"断言守卫是为"完整 GemDepth→完整 GemDepth"写的，不认识基线初始化从 checkpoint 自身探测（无 GEM/ASTT 张量→基线初始化）
48 卡首次反向即崩 expect_autograd_hooks_static_graph=True 与梯度累积的 no_sync() 不兼容；此前所有实验都是 grad_accum=1 故未暴露grad_accum>1 时改用 find_unused_parameters
5DDP 拒绝未使用参数legacy head.proj 可训练却永不收梯度，原先只在 encoder_decoder_only 时冻结，而该开关与 GEM/ASTT 互斥无条件冻结（87.372M→84.486M）
6KITTI 莫名退化 14.7%新增的 VKITTI2 场景级 split 把训练数据从 ~21k 砍到 1010 clips，且该分支不打印 clip 数，完全静默加 vkitti_scene_split 开关 + 强制打印 clip 数

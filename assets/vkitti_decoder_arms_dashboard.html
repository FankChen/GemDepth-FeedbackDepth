VKITTI 解码头对照 —— 五条路径的结论

2026-09-04 · 全部 10000 步 / crop 448 / seq_len 4 / 有效 batch 32 / seed 0 · 域内 = VKITTI held-out dense (268 帧) · zero-shot = KITTI kitti_video.json (110 帧)
一句话结论 这一轮设计的五条 arm 在 zero-shot 上无一超过 temporal 基线，最好的 finealone 仍落后 3.6%，最差的 costvol 落后一个量级。 「给解码头加结构」这个方向，在这份数据和预算下已被逐条证伪。

2. 归因拆解：域内那 5.8% 领先是什么

⚠ 先修正一个我中途说错的判断 拿到域内数据时我说「一半领先来自等效学习率 ×4」。补上 KITTI 后这个说法要改： ms(求和) 在两个协议上都优于 ms_norm(平均) ——域内 0.1123 vs 0.1155，KITTI 0.1004 vs 0.1094。 所以求和带来的高等效学习率是真实有益的设置，不是虚假增益。

但它仍然是相对 temporal 的混淆变量：temporal 用单尺度 loss， ms 用四尺度求和，两者的有效学习率本就不同。正确的表述是——

那部分增益属于「更大的有效学习率」，不属于「多尺度结构」。 要把它算进方法贡献，必须先给 temporal 也做学习率扫描，否则就是拿调参当创新。 这个对照我们从来没做过。

4. cost volume 为什么是量级失败

IGEV-MVS 的直接移植（sweep → correlate → 3D 正则 → softargmin → ConvGRU ×8 → convex 上采样）， 实现本身经过几何正确性单测（已知基线下真值深度的匹配得分最高）与 ckpt 一致性验证， 不是实现 bug。

诊断链

观察推论
scale_0（volume 的 softargmin 初值） 训练 10k 步从 2.8742 只降到 2.7081（5.8%）， 而 scale_8（8 次 GRU 后）降到 0.5220（81%） cost volume 几乎没学到东西，全部改善来自 GRU。 与 IGEV「GEV 提供好初值」的核心主张相反。
把假设覆盖率从 6/32 修到 32/32（depth_min 0.5→3.0）后， scale_0 2.7081→2.7281、AbsRel 0.4297→0.4171 「深度采样错配」这个诊断被否定。 两版参数量完全相同（207.8M / head 5.6M），是干净对照。
当前假设（未验证）：视差落在亚像素 VKITTI fx=725@1242 宽 → crop448 后 ≈863 → volume 所在的 stride 8 那层 ≈108。 相邻帧基线约 1m 时 disp = 108/Z： Z=10m→10.8px，40m→2.7px，80m→1.35px。 32 个假设全挤在约 9px 跨度内，平均间隔 0.3px —— 相邻假设 warp 出来几乎是同一个东西。 对比 IGEV-Stereo：KITTI 视差 192px@全分辨率 → 1/4 上 48px，48 个假设 ≈ 1px 间隔。 差距在几何条件，不在算法。 待实测 VKITTI 真实帧间平移分布来确认。
若要继续这条路，必须先改变视差量 ① warp_offsets (-1,1)→(-3,3)：视差 ×3，零成本； ② volume_level: 0（stride 4）：视差 ×2，显存 21GB→约 84GB（跑得起）； ③ 两者叠加 ×6 → 间隔约 1.8px，才进入 cost volume 能工作的区间。

5. 哪些 trick 还可能提点

这批负结果本身就是最强的方向信号 五条 arm 全是「给解码头加结构」，全部无正收益。而 CVPR'26 的 CARVE （2604.21713） 出发点与我们完全相同——“multi-frame models … often underperform strong per-frame methods” ——但它没提新架构，靠把 loss 与对齐的消融做干净就发了 CVPR。 两件事互相印证：剩余空间在 loss / 对齐 / 数据，不在头的结构。

1 梯度匹配 loss 消融
alpha: 0.5 → 0		 一行 config

gradient-based loss 可能反而有害		 TrimmedProcrustesLoss 的 total = ssi + 0.5·gm 里这个 0.5 从项目开始就没动过、没验过。 GemDepth 原论文也没做这个消融，拿到任一方向都是新信息。 目前投入产出比最高的一个。

联合对齐更好；local region 反而更差		 我们的 compute_scale_and_shift 在 flatten(1,2) 后对 dim(1,2) 求和 → 整段 clip 只有一组 (scale, shift)，是纯 per-sequence。 加一路 per-frame 项即可。切勿顺手做成分块对齐，CARVE 明确说那更差。
3 时间轴深度反馈 中
一次 20k 步		 我们自己的正结果 + VeloDepth (2512.10725) 现有 depth_feedback 是把上一尺度深度喂回（空间轴）， 实测是 E2a 那次最便宜的正杠杆。 同一个 idea 换到时间轴从没试过，且有自家正结果背书—— 这是唯一一条被我们自己的数据支持的结构性改动。
4 depth ↔ camera 一致性 loss 中 CARVE 消融④ CameraLoss 只把 pose_enc_list 与 GT 位姿比 L1， 位姿与深度之间没有任何一致性约束。这解释了本轮的核心怪象： quat 收敛到 0.0003，位姿学得很好却没转化成更好的深度。 复用已有 camera_head，不加新模块，最像能写进论文的方法贡献。
5 temporal 的学习率扫描 低 本看板 §2 既然「求和 vs 平均」的差异被证明是有效学习率而非结构， 那基线也该在同一个学习率尺度上被调过，否则整张对照表都建立在一个未控变量上。
6 数据配比 uniform 中 CARVE 消融③ 已量化的偏差：PointOdyssey 36.2% / TartanAir 35.4% / MVS-Synth 25.8% / VKITTI2 1.4% / DynamicReplica 1.3%（论文口径是各 20% 均匀）。 属于 mixdata 主线而非本轮 VKITTI 对照。
暂不建议做的
  • 继续加解码头结构 —— 本轮五条全负，先把 loss / 对齐吃透再回来。
  • Rethinking the State Update Gate (2605.16981) 的帧级标量门虽是零参数零训练、 Bonn −12.8% 很诱人，但它针对 recurrent / 常数显存的流式模型（TTT3R / CUT3R 那族的 state token）。 GemDepth 不是 recurrent、也没有压缩状态，不能直接套。
  • Tracktention 式显式点对应（2503.19904） 思路很正（把 ASTT 论文自称的 latent 点对应显式化），但属于新模块， 在本轮结论下应排在 loss 系动作之后。

6. 这份看板的可信度边界

  • 域内数字系统性偏乐观：VKITTI train split 的 end_idx=round(seq_num) 是 0–100%，而 val 取后 10% —— 那 268 帧训练时全部见过。 在这种设置下「域内更好」与「参数更多、更会背」无法区分， 而 ms 头恰好是 temporal 的 4 倍参数。域内只可用于归因拆解，不能作为最终判据。
  • 单 seed。历史实测噪声带 AbsRel 0.0006；本表多数对比在其 3.5 倍以上， 但 ms vs finealone（0.0012）处于边缘，不应据此排序。
  • 域内仅 1 个序列 268 帧，样本量小。
  • KITTI 用 110 帧短协议（kitti_video.json），非论文的 500 帧口径； 短协议对视频方法系统性偏乐观（漂移积累少、全局仿射对齐在短序列更易拟合）。
  • ms_iter4 因中断只有 6600 步，训练预算不匹配，不得与其它 arm 同表比较。
  • cost volume 的「亚像素视差」解释尚未实测确认，仅有内参与基线的估算推导。
